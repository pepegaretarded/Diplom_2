# Diplom_2

Автотесты API Stellar Burgers. Java 11, Maven, JUnit 4, REST Assured, Gson, Allure.
Рабочая ветка: `develop2`.

## Запуск в IntelliJ IDEA

Откройте `pom.xml` как Maven-проект, выберите JDK 11.
В панели Maven нажмите Execute Maven Goal и выполните:

```sh
mvn clean test allure:report
```

Та же команда работает из терминала в папке проекта.
Адрес по умолчанию: `https://stellarburgers.education-services.ru`.
Для другого стенда передайте `-Dbase.url=https://адрес-стенда`.

## Быстрый запуск на этом Mac

В терминале IntelliJ IDEA, открытом в папке проекта:

```sh
./run-tests.sh
```

На macOS скрипт выбирает установленную Java 11 для Apple Silicon,
а при её отсутствии — доступную Java 11,
запускает проверки и формирует Allure-отчёт. На этом Mac Java 11
для Apple Silicon зарегистрирована и выбирается автоматически.

## Сценарии

- `CreateUserTest`: уникальный пользователь, повторная регистрация,
  отсутствие email, пароля или имени (5 тестов).
- `LoginUserTest`: успешный вход, неверный email, неверный пароль,
  оба неверных значения (4 теста).
- `CreateOrderTest`: заказ с актуальными ингредиентами, без ингредиентов
  и с неверным хешем; каждый случай с авторизацией и без неё (6 тестов).

В каждой проверке проверяются HTTP-статус и тело ответа.
Ответ 500 для неверного хеша предусмотрен документацией сервиса:
проверяется HTML-текст ошибки. Тесты не меняют ожидаемые ответы под поведение стенда.

Тесты независимы. Пользователи создаются с уникальными данными и удаляются
в `@After`. Ингредиенты запрашиваются из API перед созданием заказа.
Сервис не предоставляет эндпоинт удаления заказа.

## Отчёт

Результаты: `target/allure-results`.
HTML-отчёт: `target/site/allure-maven-plugin/index.html`.
Просмотр через локальный сервер: `mvn allure:serve`.
Сохранённая копия отчёта для ревью: `reports/allure-report.zip`.
После изменения тестов обновите сохранённый архив отчёта.

В Allure записываются названия этапов без паролей и токенов.
Сырые HTTP-запросы и ответы не прикладываются.
